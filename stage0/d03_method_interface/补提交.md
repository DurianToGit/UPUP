一、方法集
1. T和*T的方法集分别包含什么？
T：仅包含值接收者的方法
*T: 包含值接收者和指针接收者的方法
2. 为什么d.Save()能够调用成功，
   但var s Saver = d可能失败？
回答：因为d的Save方法可能是指针接收者，而d可能只是值，不是指针值，所以var s Saver = d可能失败
3. 接口实现判断时，编译器是否会自动对值取地址？
回答：不一定；
如果参数为指针，实现方法为值接收者，则编译器会自动对值取地址
如果参数非指针值，实现方法为指针接收者，则编译器不会对值取地址，且会编译报错
4. 普通函数怎样通过命名函数类型实现接口？
回答：
type FuncName func(params string) error

func (f FuncName) Notify(params string) error {
   return f(params)
}
6. 接口应该定义在哪里？为什么不能说绝对由调用方定义？
回答：优先考虑接口的调用方，因为某些特定的场景下，也会定义到实现方
7. Typed Nil为什么不等于nil？
回答：因为判断接口是否为nil,需要判断，type和value都为nil,而typed Nil的type不为nil
二、NotifyFunc
实现原理：
   1. NotifyFunc 不是普通匿名函数，它是一个命名类型；
   2. Go 允许为命名类型定义方法；
   3. 定义 Notify 方法之后，NotifyFunc 的方法集中包含 Notify；
   4. Notifier 接口也要求 Notify；
   5. 因此 NotifyFunc 实现了 Notifier。

三、Typed Nil
原版本结果：err=<nil> type=*experiments.CustomError nil=false
修复版本结果：err=<nil> type=<nil> nil=true
调用方法是否一定panic：不一定，主要看方法内部是否对nil进行解引用，如果先进行nil判断安全返回，则不会panic

1. 方法调用时自动取地址和接口实现判断有什么区别？
具体方法调用：
可能自动取地址。

接口实现判断：
绝不自动取地址，只检查方法集。
2. 为什么：
   d.Save()
   可以成功，但：
   var s Saver = d
   可能失败？
因为d.Save()是具体方法调用，不是接口赋值，var s Saver = d属于接口赋值，这时候d的方法集可能和Saver的接口方法集不一致
3. *T为什么拥有T的值接收者方法？
   这是自动取地址导致的吗？
   回答：*T 的方法集包含接收者为 T 和 *T 的所有方法，这是 Go 类型系统明确规定的方法集规则，不是自动取地址或自动解引用导致的。
4. NotifyFunc为什么能够实现Notifier？
   函数本身没有接口方法，但命名函数类型可以定义方法，从而通过方法集实现接口。
5. Typed Nil调用方法时，什么情况下会panic，
   什么情况下不会panic？
   是否 panic，取决于方法内部有没有解引用 nil 接收者
   会panic:方法内部对 nil 接收者进行字段访问、解引用或其他不安全操作时，才会 panic
   不会panic:方法内部对 nil 接收者先进行nil 判断，因为没有进行解引用，所以能够安全返回不会 panic
